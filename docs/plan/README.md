## القرارات النهائية (Locked)

| البند | القرار |
|---|---|
| Backend + UI | Django 5.2 LTS + HTMX 2 + Alpine.js 3 (تطبيق واحد) |
| CSS | Tailwind CSS عن طريق الـstandalone CLI |
| Database | PostgreSQL 16 |
| Background jobs | Celery + Redis 7 |
| PDF | WeasyPrint |
| WhatsApp | بوابة Node محلية جوه المشروع (`whatsapp-gateway/`، engine: whatsapp-web.js) بدل OpenWA عشان مفيش Docker، رقم الإرسال `01000967017` |
| Email | SMTP (قابل للتغيير من الإعدادات) |
| Multi-tenancy | Shared database + `organization_id` على كل جدول |
| مرجع الهوية في الـPDF | عرض السعر الحالي (الوصف، الأرقام، الشكل) + ألوان وخطوط الـGuideline |
| شكل العرض | قائمة أسعار: الصنف · الوحدة · سعر الوحدة. **مفيش كميات ولا إجماليات** |
| رقم العرض | **كود العميل + تاريخ العرض**: `RG-2026/09/24`، والتاني لنفس العميل في نفس اليوم `RG-2026/09/24-2`. النسخة المعدّلة `-R1`. كود العميل (2–5 حروف إنجليزي) بيتقترح من أول حرفين في الاسم ويتعدّل من صفحة العميل |
| تاريخ العرض والسريان | التاريخ = النهارده، السريان = آخر يوم في الشهر (الاتنين بيتعدّلوا في كل عرض) |
| صنف خاص | مسموح في العرض، مع اختيار «ضيفه للكتالوج» (للمدير/الـowner بس) |
| الموافقات | مفيش approval، لكن المرسل لازم يراجع الـPDF النهائي بنفسه قبل ما زرار الإرسال يشتغل |
| المستخدمين في البداية | 3 تقريبًا |
| التشغيل | كل التطوير والتجربة local الأول، والنشر على السيرفر آخر مرحلة |
| لغة الواجهة | عربي RTL، مجهّزة لـi18n |
| اسم النظام | **مرسول البرق** (repo: `marsool-albarq`) |
| مرجع شكل الـPDF | `assets/reference-quotation.pdf` (العرض القديم المقسّم بالأقسام + سطر سلسلة الفنادق) — مش عرض الـ72 |
| أرقام رأس العرض | 0653451404 · 01060777030 · 01000967017 |
| الكتالوج | 72 صنف بالظبط. الأسماء والتقسيم زي موقع البرق (al-barq-five.vercel.app/ar/products)، والوحدات من `assets/products-72-source.pdf` |
| تقسيم المنتجات | مستويين: **مجموعة** (6) ← **قسم** (21) ← منتج. صف القسم في الـPDF بيعرض **القسم الفرعي بس** |
| الأسعار | **مفيش سعر مرجعي للمنتج.** السعر بيتكتب في كل عرض، والنظام بيقترح آخر سعر اتبعت لنفس العميل (ذاكرة الأسعار) |
| إدارة الكتالوج | المنتجات والأقسام والمجموعات بتتضاف وتتعدّل وتتعطّل وتترتب من الواجهة (owner)، مش بس من الـimport |
| الأدوار | 1 owner + 2 sales |
| العميل في العرض (A) | العرض بيتوجه لـ**فندق معين** (ممكن يكون تابع لسلسلة/مجموعة) + **مسؤول معين** فيه |
| استيراد العملاء (H) | من `ارقام العملاء والضرائب.xlsx`: 15 عميل بس، والموردين مستبعدين (`manage.py import_customers <file>`) |
| الـsales والعملاء (F) | الـsales يشوف ويعدّل كل العملاء |
| التشغيل على الجهاز | **من غير Docker** (مفيش WSL ولا صلاحيات Admin): `run.bat` بيشغّل Postgres 16 مدمج + Django. Docker للسيرفر بس |
| الـPDF | **Chromium (Playwright)** بدل WeasyPrint، لأن WeasyPrint محتاج GTK على Windows (البديل المذكور في 05-pdf-generation) |

## الـWorkflow الأساسي

```
اختيار العميل → اختيار المسؤول → إضافة المنتجات → الأسعار → إصدار → مراجعة الـPDF ✓ → إرسال
```

كل ده في **شاشة واحدة** + شاشة Preview/Send.
